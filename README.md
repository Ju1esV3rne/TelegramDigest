# TelegramDigest

Локальный инструмент для ежедневной сводки сообщений из домовых Telegram-чатов.

Скрипт подключается к Telegram от вашего аккаунта, читает сообщения из выбранных
групп за заданный период и сохраняет их в JSON. Дальше этот текст передаётся в
облачную модель через OpenRouter, а готовая сводка отправляется в отдельный
Telegram-канал «Домовой дайджест» ботом @OdinDigestBot.

## Возможности (на текущем этапе)

- Сбор сообщений из списка чатов за последние N часов
- Генерация краткой русской сводки через OpenRouter (только факты из сообщений,
  без выдуманных событий)
- Отправка сводки в Telegram-канал через Bot API — только по явному флагу
- Защита от повторной публикации: один и тот же дайджест не уходит в канал дважды

## Установка

```powershell
uv sync
```

## Настройка

### 1. Секреты — `.env`

Скопируйте `.env.example` и заполните:

- `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` — с [my.telegram.org](https://my.telegram.org)
  -> API development tools -> Create application (Platform: Desktop).
- `OPENROUTER_API_KEY` — ключ с [openrouter.ai/keys](https://openrouter.ai/keys).
- `OPENROUTER_MODEL` — модель, например `openrouter/free`.
- `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather.
- `TELEGRAM_TARGET_CHAT_ID` — ID канала-получателя сводки (например `-1001234567890`).

Файл `.env` уже добавлен в `.gitignore` и в Git не попадает.

### 2. Чаты и период — `config.toml`

```toml
groups = [-1001122753791]
hours = 24
output = "data/messages.json"
```

## Запуск

Полный цикл (сбор → саммари → публикация) — только с явным флагом:

```powershell
uv run python main.py --publish
```

Безопасный режим по умолчанию (только генерация, без публикации):

```powershell
uv run python main.py
```

Не запускать сборщик, а взять уже готовые данные:

```powershell
uv run python main.py --skip-collect
```

Сгенерированная сводка показывается в консоли и сохраняется в
`data/summary_preview.txt`.

### Как запускать каждый этап отдельно

| Этап | Команда |
|---|---|
| Сбор сообщений | `uv run python collect_messages.py` |
| Генерация сводки на готовых данных | `uv run python main.py --skip-collect` |
| Публикация в канал | `uv run python main.py --publish` |
| Проверка отправки ботом | `uv run python test_bot.py` |
| Офлайн-проверка логики сводки | `uv run python test_summary.py` |
| Офлайн-проверка публикации и защиты от повторов | `uv run python test_publish_flow.py` |
| Офлайн-проверка отправки и ошибок Telegram | `uv run python test_sender.py` |

## Как формируется сводка

Сообщения из `data/messages.json` упаковываются в запрос ограниченного размера:
одно сообщение обрезается до 1200 символов, одна часть запроса — до 12000
символов. Каждая часть обращается к модели, и модель возвращает разделы:

```json
{"sections": [{"title": "Проблемы дома", "items": ["нет горячей воды"]}]}
```

Разделы с пустым содержимым в результат не попадают, повторы одного события
объединяются. Модели предписано: брать только факты из сообщений, ничего не
выдумывать, отбрасывать эмоциональный шум и сохранять существенные детали
(даты, сроки, номера подъездов, названия служб).

Ответ модели проверяется перед публикацией:

- заголовки разделов должны быть из разрешённого списка (похожие формулировки
  вроде «Отключения» приводятся к разрешённому заголовку);
- пункты не должны быть шаблонными заглушками («пункт 1», «пример»);
- если проверка не пройдена, запрос повторяется (до трёх попыток) с подсказкой,
  что именно не так;
- если корректная сводка не получена, цикл прерывается с ошибкой и **ничего
  в канал не отправляется**.

Пустой ответ модели (исчерпан лимит токенов) — тоже повод для повтора, а не
для публикации.

## Повторная публикация

Хеш текста публикации хранится в `state/published.json`. Дайджест помечается
как отправленный **только после** успешного ответа Telegram. Из этого следует:

- если сводка уже отправлялась, повторный запуск с `--publish` её пропустит;
- если генерация или отправка сорвалась, дайджест остаётся неопубликованным и
  уйдёт в канал при следующей попытке.

## Устранение типичных ошибок

| Сообщение | Что делать |
|---|---|
| `OPENROUTER_API_KEY` не найден | Впишите ключ в `.env` |
| Нет сообщений за период | Проверьте `hours` в `config.toml` |
| HTTP 401, `ok=false` | Токен бота недействителен, проверьте у @BotFather |
| HTTP 429 | Исчерпан дневной лимит бесплатных запросов к OpenRouter (без кредитов их всего 100 в сутки). Лимит обновится завтра; либо добавьте кредиты на openrouter.ai и укажите платную модель в `OPENROUTER_MODEL` |
| Telegram вернул HTTP 429 | Слишком часто отправляем — Telegram просит подождать (время ожидания указано в ответе). Дайджест при этом не отмечается как опубликованный |
| Модель вернула пустой ответ | Модель исчерпала лимит токенов, замените модель в `OPENROUTER_MODEL` на другую |
| Модель не вернула корректную сводку | Ответ не прошёл проверку формата; попробуйте другую модель или повторите позже |
| Текст длиннее 4096 символов | Telegram не примет такое сообщение целиком |

## Безопасность и приватность

- `.env`, файлы сессий (`*.session`), папки `state/` и `data/` исключены из Git.
- В модель уходят только тексты сообщений из чата — никаких дополнительных данных.
- Токен бота присутствует в URL запроса, но нигде не печатается: в логах видно
  только адрес `api.telegram.org` без токена.
- Для чтения сообщений используется ваш обычный аккаунт, для публикации —
  отдельный бот. Бот не имеет доступа к чатам жильцов.

Замечание по приватности: тексты сообщений жильцов уходят на внешний сервис
OpenRouter. В них могут встречаться имена, номера квартир и жалобы на
конкретных людей. Если это нежелательно, ограничьте состав чатов в
`config.toml` или сократите период сбора.
